# Stellar XDR Shape Corpus

A language-neutral corpus of rare but valid Stellar ledger shapes, captured from the network as raw XDR, with the values a correct decoder must produce. Around it: a replay harness that runs the corpus through a real indexer and reports `pass`, `mishandled` or `dropped` per shape, a Go linter for indexer code, and the outline of an indexer-hardening guide.

This repository is the working prototype for the SCF RFP *XDR/CAP-Coverage Audit Tool and Indexer-Hardening Guide*. Everything here runs today; what is still planned is marked as planned.

## Corpus entries

| Entry | CAP | Testnet ledger | Transaction | What it exercises |
| --- | --- | --- | --- | --- |
| `cap40-signed-payload-signer-max-payload` | CAP-0040 | 5699703 | `68e7d549…` | Signed-payload signer with a 64-byte payload (the maximum), added through SetOptions |
| `cap27-muxed-source-and-destination-id-extremes` | CAP-0027 | 5699707 | `fae7b0f2…` | Muxed source with id 18446744073709551615 (u64 max) and muxed destination with id 0 |
| `cap73-sac-created-trustline` | CAP-0073 | 5699714 | `dab291a4…` | Trustline created by the Stellar Asset Contract `trust()` call, with no ChangeTrust operation and no contract event |
| `cap67-sac-transfer-to-muxed-address-max-id` | CAP-0067 | 5701159 | `713e56b3…` | SAC `transfer()` to a muxed `ScAddress` with id u64 max; the event topic carries the base G account and the id travels in `to_muxed_id` |

Each entry lives in `corpus/entries/<id>/`. [corpus/manifest.json](corpus/manifest.json) indexes them: CAPs, protocol version, network and passphrase, where the bytes came from, the shapes covered, the sightings that motivated the entry, sha256 of every file, and the expected values as JSON Pointers into the rs-stellar-xdr JSON form. The manifest is generated by [tools/build_manifest.py](tools/build_manifest.py), which reads every expected value back from the bytes and refuses to write if one does not match.

## Replay harness

[harness/](harness/) runs the corpus through wallet-backend's real indexer at the commits before and after each fix. No Docker or Postgres: the adapter calls the same `Value()` and `Scan()` that the COPY path uses, so it shows which bytes would be stored and what reads back. Full method, commits and per-commit evidence are in [harness/README.md](harness/README.md).

| Sighting | Pre-fix commit | Fixed commit |
| --- | --- | --- |
| wallet-backend#731 | `dropped` at `764a4f5b` | `pass` at `c152783c` |
| wallet-backend#729 | `dropped` at `2a0a84ea` | `pass` at `2c873353` |
| wallet-backend#716 (signed payload) | `mishandled` at `79ea2acd` | `pass` at `2c873353` and `71625b21` |
| wallet-backend#792 (`to_muxed_id` on a muxed destination) | `mishandled` at `a9bac8d2` | `pass` at `09303667` |

The harness also surfaced one finding of its own: every commit in that window pins go-stellar-sdk v0.7.3, which cannot decode a protocol 30 ledger header (`STELLAR_VALUE_SIGNED_MS`, CAP-0088). An indexer left on that version stops at the upgrade. The fixes were measured by bumping only that dependency to v0.8.0.

## Run it

```bash
# Byte round trip and manifest check (Rust + Python)
cargo build --release --locked --manifest-path tools/roundtrip/Cargo.toml
pip install "jsonschema>=4.18,<5"
python tools/build_manifest.py --check
python tools/check_schema.py

# Linter tests (Go)
cd linter && go test ./...

# Capture new entries on testnet (Node, ephemeral keys funded by friendbot)
cd tools && npm ci && node capture-testnet.mjs cap40
```

## Layout

| Path | Content |
| --- | --- |
